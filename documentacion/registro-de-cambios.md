# Registro de cambios del proyecto

Este registro resume los principales avances de la fase de análisis y documentación de Educación Virtual RD.

| N.º | Cambio o avance | Resultado |
|---|---|---|
| 1 | Organización de requisitos funcionales | Se definieron los requisitos RF01–RF05 para registro, acceso, cursos, evaluaciones y reportes. |
| 2 | Historias de usuario y criterios de aceptación | Se documentó qué necesita el usuario y cómo se podría comprobar cada función. |
| 3 | Modelado del sistema | Se incorporaron archivos fuente de casos de uso, clases, secuencia y actividades. |
| 4 | Definición de arquitectura | Se describieron las responsabilidades del frontend, backend, API y base de datos. |
| 5 | Seguimiento mediante Issues | Se revisaron las descripciones y se cerraron las tareas de definición documental atendidas. |

## Alcance de estos cambios

Los cambios se refieren a la documentación y al modelado. No significan que los módulos estén programados o que hayan superado pruebas funcionales. La implementación y la verificación técnica deben registrarse por separado cuando se realicen.

## Convención recomendada para próximos cambios

Usar mensajes directos que expliquen la modificación, por ejemplo:

- Documentar reglas de validación del registro.
- Añadir casos de prueba para el inicio de sesión.
- Revisar el diagrama de clases.
- Implementar consulta de cursos.
- Corregir validación de evaluaciones.

Cada commit debe corresponder a un cambio concreto y comprobable.
